# 剪贴板拟人打字机 (clipboard-typer)

一个 Windows 后台小工具：复制任意文本后按 `Ctrl+Shift+V`，它会把剪贴板里的内容**像真人手敲键盘一样逐字打出来**，输出到你鼠标点击的目标输入位置。

适合往不支持自动填充的界面（聊天框、网页表单、远程桌面里的输入框等）"手打"长文本。

## 功能特性

- **全局热键 `Ctrl+Alt+V`**：任意界面下复制 → 点击目标位置 → 按热键，剪贴板内容逐字打出
- **拟人打字节奏**：每字 40~120ms 随机抖动，另有 3% 概率插入 0.3~0.7s 的"思考停顿"，节奏全部可调
- **完全绕过输入法**：所有字符走系统 Unicode 注入（`KEYEVENTF_UNICODE`），中文输入法开着也不会把英文变成拼音候选字（实测 pynput 默认的真实键码方案会被中文输入法拦成 `Hello → 饿了咯`，本项目已规避）
- **字符全覆盖**：中英文、数字、标点、大写、emoji（自动拆 UTF-16 代理对）；换行敲真实回车键、制表符敲真实 Tab 键
- **随时中止**：打字过程中按 `Esc` 立即停止（打错目标时的后悔药）
- **后台常驻无窗口**：不占任务栏，不修改剪贴板内容，纯本地运行不上传任何数据

| 热键 | 作用 |
|---|---|
| Ctrl+Alt+V | 把剪贴板内容逐字打出来 |
| Esc | 打字过程中随时中止 |
| Ctrl+Alt+Q | 退出脚本 |

> **为什么默认热键不是 Ctrl+Shift+V？** Word、VS Code、Teams、Slack 等大量软件把 Ctrl+Shift+V 定义为"粘贴为纯文本"——在这些软件里按下它，目标软件会先自己粘贴一遍，脚本再逐字打一遍，内容就出现两份。脚本侧无法拦截（热键监听不吞按键），所以默认改用冲突面小得多的 Ctrl+Alt+V。如果你明确要改，编辑 `clip_type.pyw` 顶部的 `HOTKEY_TYPE` 即可（如 `'<f9>'`）。

## 环境搭建

### 依赖

- Windows 10 / 11
- Python 3.8+（本项目在 3.10.5 上开发验证）
- 两个纯库依赖：

```bash
pip install pynput pyperclip
```

> **多版本 Python 机器注意**：务必给"实际会运行本脚本的那个 Python"装依赖。查看 `python --version` 确认的是哪一个；也可以用绝对路径安装，例如 `D:\python\python3105\python.exe -m pip install pynput pyperclip`。

### 启动方式

- **方式 A（推荐）**：双击 `start_clip_type.vbs`。它会用**写死的 pythonw 绝对路径**隐藏运行脚本，无黑窗口。换成你自己的机器时，用记事本打开 vbs，把里面两处路径改成你的 `pythonw.exe` 和本项目的 `clip_type.pyw` 路径即可。
- **方式 B**：命令行运行 `python clip_type.pyw`（有控制台输出，便于调试）。

### 双击 `.pyw` 没反应？（常见坑）

两个典型原因，本项目两种都实际踩到过：

1. **`.pyw` 文件关联缺失**：`.pyw` 指向的文件类型类没有注册打开命令，双击后系统什么都不做。管理员 cmd 执行以下命令可修复（路径换成你的）：
   ```bat
   ftype Python.NoConFile="D:\python\python3105\pythonw.exe" "%L" %*
   ```
2. **默认 Python 没装依赖**：机器上有多个 Python 时，双击 `.pyw` 会用系统默认解释器（`py -0p` 可查看），那里可能没装 pynput。用 vbs 启动器写死路径可彻底绕开这两个问题。

## 使用方法

1. 双击 `start_clip_type.vbs` 启动，脚本后台常驻（任务管理器里对应 `pythonw.exe`）
2. 复制任意文本（中英文 / 数字 / 标点 / emoji 均可）
3. 鼠标点击目标输入位置，让光标落在那里
4. 按 **Ctrl+Alt+V**，剪贴板内容开始逐字打出；打完自动停止

**自测**：打开记事本点一下输入区，运行 `python clip_type.pyw --test`，3 秒后它会向当前焦点窗口打一段固定的中英文混合测试文本（含 emoji、换行、Tab），打字中按 Esc 可中止。

**开机自启**：`Win + R` → `shell:startup` → 把 `start_clip_type.vbs` 的快捷方式放进去。

## 参数调整

打开 `clip_type.pyw` 顶部"可调参数"区：

| 参数 | 含义 | 默认值 |
|---|---|---|
| MIN_DELAY / MAX_DELAY | 相邻两字符的间隔区间（秒） | 0.04 / 0.12 |
| PAUSE_CHANCE | 出现"思考停顿"的概率（0~1） | 0.03 |
| PAUSE_MIN / PAUSE_MAX | 思考停顿时长区间（秒） | 0.3 / 0.7 |
| START_DELAY | 按热键后等多久开始（秒），留出松开修饰键的时间 | 0.4 |
| HOTKEY_TYPE / HOTKEY_QUIT | 触发打字 / 退出脚本的热键 | Ctrl+Shift+V / Ctrl+Alt+Q |

想要快就调小间隔区间（如 0.015 / 0.05），想要"更像人"就调大区间并提高 `PAUSE_CHANCE`。

## 工作原理

1. 热键监听：`pynput.GlobalHotKeys` 注册全局热键（只响应真实物理按键），另有独立监听器捕获 `Esc` 用于中止
2. 读剪贴板：`pyperclip`（剪贴板被其他程序占用时自动重试一次）
3. 逐字输出：`ctypes` 直接调用 `SendInput`，以 `KEYEVENTF_UNICODE`（VK_PACKET 机制）注入字符——这是 Windows 官方的"无键码字符注入"通道，与 AutoHotkey 的 `SendText` 同机制，不经过任何键盘布局与输入法；超出 BMP 的字符（emoji）自动拆成 UTF-16 代理对
4. 换行 `\n` / 制表符 `\t` 例外：它们用 pynput 敲**真实回车键 / Tab 键**（聊天软件里换行才会真的发送）；`\r\n` 的 `\r` 自动忽略
5. 每个字符之间按参数区间的随机时长 sleep，按概率插入思考停顿

### 为什么不直接模拟按键码？

开发中实测：pynput 默认对小写字母/数字发送真实虚拟键码，在有中文输入法时会被输入法拦截进入拼音组合，`Hello World` 会被打成 `饿了咯W偶然来到`。Unicode 注入对所有字符统一处理，任何输入法状态下输出都正确。代价是个别不认 VK_PACKET 的程序（部分游戏、老软件）收不到字符，属正常现象。

## 注意事项 / FAQ

- **打字过程中不要碰键盘鼠标**，会混入你自己的输入；打错目标按 Esc 中止重来
- **同一时间只运行一个实例**，重复启动会把内容打两遍
- **目标窗口以管理员权限运行时收不到字符**（Windows UIPI 限制，低权限进程无法向高权限窗口注入输入）——此时以管理员身份运行本脚本即可
- 剪贴板为空或是图片时，按热键不会做任何事
- 启动异常先看同目录 `error.log`（主线程与监听线程的异常都会记录）
- 若按热键完全无反应：确认目标窗口拿到了键盘焦点（点一下它的输入区），并确认只有一个脚本实例在跑
